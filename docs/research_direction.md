# 从 general DAG 框架到可检验的研究问题

## 当前证据

框架已经能执行 `read_dag`、`spawn`、`yield`、`conclude` 和独立 finalizer；[HotpotQA 三题预实验](../benchmarks/hotpotqa/README.md)表明，自由模型调用倾向于直接回答。强制模型规划两名证据节点能跑通完整 DAG，但在相同输出上限下，与固定双工作者同为联合正确 1/3，且多一次规划调用、增加 905 token。三题不能支持性能结论，且曾用于调试，不应当作独立测试集。

后续加入了 `read_docs` 和根节点的证据完整性门控。最初门控把格式错误也当成证据不足，在五题上全部生成节点；修正后出现直接结束与生成验证节点两种动作，但小样本仍暴露无效文档请求和支持事实不完整。这些题也用于调试，不可作为确认性比较。当前最值得解决的是**读到哪些证据、证据是否足够支持结论**，而非增加节点数量。

## 可能的主问题

**在固定模型和总预算下，节点看到哪些证据状态时应继续读取、生成新上下文，或者直接结束？** 决策单位是一次执行中的状态，而不是为每道题预先固定一个两工作者结构。候选状态包括：已核对的证据数、尚未覆盖的线索、互相矛盾的候选答案、预计新增调用成本，以及 DAG 中已有节点的结果。仅统计引用数量不够：两条引用可能不支持同一结论。目标是提高答案与证据的联合正确率，而不是单独提高生成节点数。

这只是待验证方向。已有 [Recursive Language Models](https://arxiv.org/abs/2512.24601) 研究递归子调用；[DAGent](https://arxiv.org/abs/2609.39154) 已提出依据证据逐步扩展 DAG；[AFlow](https://arxiv.org/abs/2410.10762) 搜索工作流。宽泛的“动态生成 DAG”缺乏新颖性。更窄的贡献只有在**显式证据缺口和交接成本能改善同预算动作选择**，并超过这些近邻基线时才成立。[Scaling Agent Systems](https://arxiv.org/abs/2512.08296)也提示任务形态和协调开销会改变多智能体收益。

## 下一轮实验

1. 预先冻结 HotpotQA dev 中按 `bridge/comparison` 和难度分层的样本，不再用前三题调提示。所有条件使用相同文档、模型、总 token 上限和答案格式。
2. 对照：单节点；同预算重试或独立采样；固定两工作者；自由动态；基于证据缺口的规则路由；再考虑模型学习的路由。记录每次 `read_dag/spawn/yield/conclude`、证据读取、支持事实完整性、模型调用、token 与延迟。
3. 对失败按阶段归因：规划把相关文档分错、工作者漏掉句子、finalizer 丢失已找到的证据、或直接回答过早。若规则路由不能比固定和单节点稳健，就不应先训练复杂控制器。
4. 在补齐检索工具和更长程任务后，再转向 GAIA 或固定语料的研究任务；HotpotQA 主要验证多跳证据与动态动作机制，不能代表开放式深度研究。

软件框架的价值与研究贡献应分开评价。仓库可作为可复现实验底座；论文需要一个在强基线和样本外任务上成立的具体决策规律。

## 2026-11-26：冻结样本后的验证

[HotpotQA 60 题](../benchmarks/hotpotqa/README.md)中，单节点、固定两工作者、自适应 DAG 的联合正确分别为 22、17、17 题；自适应有 12 次错误。分开看，comparison 为 14/13/12，bridge 为 8/4/5。首次 10 道 comparison 中固定工作者的优势没有在第二批 20 道上保持。

[MuSiQue 16 题](../benchmarks/musique/README.md)更明确地覆盖 2 跳和 4 跳，但结果也不支持当前 DAG 策略：2 跳联合正确为单节点 1/8、固定 1/8、自适应 2/8；4 跳分别为 2/8、0/8、1/8。自适应在两组各有 2 次预算错误，总 token 使用分别为单节点的约 2.35 倍和 3.15 倍。MuSiQue 样本很小，不能外推整体数据集；但足以否定“当前实现已有明显收益”的说法。

[fan-out 机制测试](../benchmarks/routing/README.md)显示一个更窄、可解释的收益条件：8 个后继中只有 1 个需要 8,192 字符的中间结果时，直接广播使后继上下文共暴露 65,536 字符，共享存储按需读取只暴露 8,192 字符。若 8 个都需要，两者暴露量相等而读取多出 8 次。这是传输字符量的确定性对照，不是模型 token、时延或答案质量实验。

因此下一步应把主实验切到**一份长中间产物、多后继、实际需求稀疏且可观测**的工作流：先实现每条边指定接收者，再比较直接送达、共享存储、与基于产物大小及预期读者数的路由。冻结任务与路由阈值后，记录实际 prompt token、存储读取、墙钟时间和最终任务正确率；加入相同预算的单节点及全直接/全存储基线。现有 HotpotQA/MuSiQue 结果保留为负面证据，不能只报告有利子集。

## 2026-11-27：固定 DAG 的真实模型路由实验

已加入按边定向发送，并在 [预先冻结的 MuSiQue 任务](../benchmarks/routing/README.md)上运行 `deepseek-flash`：三组各有 1 个需要共享长报告的四跳问题和 7 个有局部材料的单跳问题。共 24 个不同任务，比较直接广播、定向发送、共享存储按需读取。三者正确数分别为 13、13、12；实际 prompt token 分别为 58,104、11,232、11,232，后两者相对广播减少 80.7%。共享存储发生 3 次读取，定向发送没有读取。顺序执行耗时分别为 12.88、11.52、12.68 秒，样本与网络波动不足以支持时延差异结论。

这个结果确认**不要把长产物广播给已知不需要它的节点**。定向发送与共享存储的 prompt token 完全相同，因为实验预先知道唯一读者；两者在一题上的正确率差别来自相同 prompt 的不同模型输出，不能解释为路由提升了推理能力。当前存储是内存读，没有远程存储延迟或权限发现成本。

后续研究焦点应转为**未知读者时的决策**：让节点根据轻量元数据判断是否读取，或让调度器根据产物长度、读者概率和读取成本选择路由。需要在读者集合未知于控制器的独立任务上冻结阈值，并比较定向路由、全广播、全存储及同预算单节点。正确率和总成本必须同时报告。

## 2026-11-27：多级动态 DAG 的分叉题诊断

针对 PPT 的运行中扩图设想，[MuSiQue 多级实验](../benchmarks/musique/README.md)冻结了未用过的四跳链式与分叉型题，比较单次读取、单节点复查、单层双分支 DAG 和允许一级子节点继续生成孙节点的 DAG。先用各组 2 题诊断动作，再锁定“子节点显式判断是否拆分”的策略；后 6 题作为每组样本外测试。

分叉型 6 题已完整跑完：联合正确分别为 1、0、0、2 题；多级 DAG 有 8 次子节点扩展，消耗 83,649 token，单次读取为 15,377 token。两道多级正确题的单层 DAG 实际已经读到全部四个标准支持段落，差异发生在答案和证据整合，不足以证明新分支发现了缺失材料。多级策略也在链式诊断题上触发，结构判断不准。链式样本外运行起初遇到 API `HTTP 402 Payment Required`，充值后按锁定策略续跑完成：四种策略的联合正确均为 0/6，多级生成 7 次孙节点扩展，花费 69,609 token，单节点花费 16,585 token，且多级有一次预算超限。该小样本未证明能根据链式／分叉结构有效选择是否扩图。

因此当前动态 DAG 的可能收益点仍只是待验证假设：执行后发现原计划漏掉的必要分支、把不同证据隔离在局部上下文中以减少整合错误、或对简单题及时停止以节省调用。现有策略在第二、第三点没有稳定证据，且多级生成显著增加成本。下一轮必须先解决检索与证据汇总，再用未见的固定语料深度研究任务检验是否真的取回了单层策略没有找到的必要证据。当前顺序调度器不能检验并行时延收益。

对保存轨迹的[逐题审计](../benchmarks/musique/README.md#trace-audit-did-grandchildren-find-new-required-evidence)进一步确认：五道可配对的分叉题中，单层与多级各读到 18/20 个标准支持段落，多级相对单层新增的标准段落为 **0**；最终答案引用的标准段落分别为 12/20 与 17/20。因此这次观察到的正确率差异发生在已读证据的使用阶段，尚不能支持“动态扩图找回遗漏证据”的主叙事。对额外调用、上下文隔离和模型随机性的作用还无法单独归因。

## 2026-11-27：带检索的动态扩图留出测试

加入 `search_docs` 和局部 BM25 检索后，在 [BrowseComp-Plus 候选池实验](../benchmarks/browsecomp/README.md)中冻结 2 道诊断题与 6 道留出题。每题的候选池由标准证据、gold 文档和负例文档构成，标签只用于评分；这比官方完整语料检索容易，不能称为官方 benchmark 分数。三种策略共用模型、索引、逐题 32,000 观测 token 上限；单层与动态还共用初始两线索规划。

六道留出题的严格答案匹配为：单节点 **4/6**（67,936 token）、固定两分支 DAG **4/6**（151,743 token）、证据缺口动态 DAG **0/6**（202,684 token）。动态策略共生成 9 次孙节点分支，六题均在最终答题前超预算；在其中两题，孙节点确实读到了固定 DAG 未读到的标注 gold 文档，但未转化成答案。这证明当前自由缺口判断与扩图策略的协调成本压倒了潜在检索收益，不能声称动态 DAG 有明显净收益。固定 DAG 有一题答对而单节点未答对，同时也有一题相反；6 题规模只能当机制诊断。

下一版研究假设应收窄为**成本约束的证据缺口决策**：先定义可观测的缺口（所需事实、已读文档、已有节点覆盖范围），仅在预期新证据价值超过新增检索、上下文和汇总成本时扩图；同时允许继续在原节点搜索或直接结束。先在诊断集固定门控、每节点读取上限和保留给 finalizer 的预算，再冻结新的留出集对比单节点、固定 DAG 和同预算动态策略。当前六道题已用于判断方法失败，不能在它们上面反复调门控后当作独立验证。
